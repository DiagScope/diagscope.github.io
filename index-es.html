Hay fallos que no fallan lo bastante fuerte.

Datadog, Grafana y New Relic solo pueden mostrarte las señales que tu código realmente produjo. Si el log, la métrica o el contexto nunca se escribieron, ningún dashboard los va a inventar durante un incidente.

  • 01 Una excepción se captura y se descarta en silencio — sin log, sin métrica, sin relanzamiento.
  • 02 Un fallo se convierte en un resultado que parece normal, y la causa original desaparece con él.
  • 03 Se envía un mensaje a Kafka, pero nadie comprueba si el broker llegó a confirmarlo.
  • 04 Un ID de pago termina como tag de una métrica — y tu factura de observabilidad se infla con él.

Cómo funciona

DiagScope se ejecuta antes de que Datadog, Grafana o New Relic vean ninguna señal — directamente sobre tu código fuente, en tu editor o en tu CI.

Apunta a un proyecto

Un repositorio Maven por ejecución. Sin servidor, sin credenciales, el código nunca sale de tu máquina.

Encuentra tus puntos de entrada

Endpoints REST, listeners de Kafka, tareas programadas — los lugares donde empieza un flujo real.

Sigue el flujo

Llamadas locales, unos pocos niveles de profundidad. Cuando no puede estar seguro, lo dice — nunca disfraza una suposición de hecho.

Obtienes un informe

Qué falta, dónde, y con cuánta confianza lo dice DiagScope — archivo, línea, y una sugerencia concreta.

Qué revisa hoy

La Fase 1 es deliberadamente pequeña — cuatro comprobaciones elegidas porque casi nunca son cuestión de estilo, y casi siempre vale la pena corregirlas.

Catch silencioso

Una excepción desaparece

Se captura y nunca se registra, se propaga ni se actúa sobre ella. Pase lo que pase, nadie lo sabrá.

catch (Exception e) { }
Conversión de fallo silenciosa

Un fallo parece un éxito

La excepción se convierte en false, null, o Optional.empty() — y la causa original desaparece con ella.

catch (Exception e) { return null; }
Envío a Kafka ignorado

Publica, y espera lo mejor

El método retorna antes de que el broker confirme, sin ningún callback vigilando un fallo de entrega.

kafkaTemplate.send(topic, event);
Tag de métrica de alta cardinalidad

Un ID único se vuelve tag de métrica

paymentId, un UUID, un request ID — usarlo como tag de una métrica dispara la cardinalidad río abajo.

.tag("paymentId", id.toString())
Esto es una fase temprana. La Fase 1 existe para probar una sola cosa: si estos hallazgos se sostienen en código real, con pocos falsos positivos. La instrumentación orientada a aspectos, la comparación con dashboards de Grafana y los flujos entre servicios están planeados — pero solo si esta primera apuesta, más pequeña, se demuestra primero.
