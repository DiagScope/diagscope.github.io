Análisis estático · Java & Kotlin

Encuentra el código que oculta fallos antes de que producción los revele

DiagScope escanea proyectos Java y Kotlin buscando patrones que destruyen silenciosamente la evidencia de diagnóstico — excepciones silenciadas, transacciones faltantes, llamadas HTTP sin timeout. Se ejecuta localmente, ningún dato sale de tu máquina.

$ brew tap DiagScope/tap && brew install diagscope
$ diagscope scan --project .

Sin build necesario  ·  Java & Kotlin  ·  Spring / Quarkus / Micronaut

Qué encuentra

Código que falla silenciosamente

Excepciones, transacciones, concurrencia, Kafka, rendimiento, seguridad y más. Cada hallazgo identifica el entrypoint que llega al problema.

SILENT_CATCH

Excepción silenciada

Capturada y nunca logueada ni relanzada — el fallo simplemente desaparece.

FUTURE_GET_WITHOUT_TIMEOUT

Llamada bloqueante sin timeout

Un hilo queda bloqueado indefinidamente esperando un resultado que puede no llegar.

MISSING_TRANSACTION_ANNOTATION

Escritura sin transacción

Si un paso posterior falla, la primera escritura queda confirmada sin poder revertirse.

HTTP_TIMEOUT_NOT_SET

Llamada HTTP sin timeout

Un upstream lento agota el pool de hilos y derriba todo el servicio.

N_PLUS_ONE_QUERY_RISK

Query N+1 en bucle

Una llamada a base de datos dentro de un bucle — escala linealmente y se degrada con los datos.

KAFKA_SEND_RESULT_IGNORED

Envío Kafka no observado

El resultado del publish se descarta — los fallos son invisibles para quien llamó.

Instalación

Listo en dos comandos

01 — Agrega el tap

Instala via Homebrew

$ brew tap DiagScope/tap

Apunta a un proyecto

Reporte

Cómo es el reporte

Abre report.html en cualquier navegador. Es un único archivo autocontenido: sin servidor, sin red. Ordena qué corregir primero, filtra por severidad y confianza y muestra la ruta de llamadas desde el entrypoint hasta cada hallazgo.

Cómo usar

Comandos principales

Escanear un proyecto Spring

Endpoints REST, Kafka listeners y jobs programados se detectan automáticamente como entrypoints.

$ diagscope scan --project .

Gate de CI — solo hallazgos nuevos

Falla el build solo en hallazgos introducidos en este PR, dejando los existentes para después.

$ diagscope scan --project . --update-baseline $ diagscope scan --project . --baseline --fail-on ERROR

Explicar un hallazgo

Obtén la descripción completa, por qué importa y cómo corregirlo.

$ diagscope explain SILENT_CATCH

Consultar las reglas

El catálogo crece con cada versión, así que pregúntale a la herramienta: lista todas las reglas con severidad, categoría y versión.

$ diagscope rules $ diagscope rules --format JSON
Con asistentes de IA

Deja que tu asistente de código revise su propio trabajo

Cuando el equipo genera código con un asistente, DiagScope puede ejecutarse antes de que el asistente diga que terminó. Así las excepciones tragadas y los logs ausentes se corrigen en la misma sesión y no en producción.

Configúralo una vez

Escribe un bloque corto de instrucciones en AGENTS.md y CLAUDE.md y añade un hook de Claude Code que escanea los archivos modificados cuando termina la tarea. El contenido existente nunca se sobrescribe.

$ diagscope init-agent

Salida pensada para asistentes

Texto simple y compacto, con el peor problema primero y una línea de corrección para cada uno. Unos 3 KB donde el informe en Markdown tiene 22 KB. El código de salida sigue viniendo de tu gate.

$ diagscope scan --format AGENT \ --files src/main/java/PaymentService.java

Elige el rigor

La tolerancia vive en diagscope.yml, así que se revisa junto con el código. Falla en errores de alta confianza, tolera algunos avisos o define un perfil más estricto para ramas de release.

gate: failOn: - severity: ERROR confidence: HIGH maxFindings: { WARNING: 20 }

El hook automático es para Claude Code. Otros asistentes leen las instrucciones de AGENTS.md y ejecutan el mismo comando, pero nada los obliga. Un escaneo tarda de 1 a 15 segundos según el tamaño del proyecto, por eso la comprobación se ejecuta al final de la tarea y no tras cada edición. Se le indica al asistente que no silencie un hallazgo sin preguntarte.
