¿Este código se explicará solo
cuando falle en producción?

DiagScope sigue flujos de ejecución reales y encuentra código que destruye silenciosamente la evidencia de diagnóstico — antes de que un incidente te obligue a descubrir que nunca estuvo ahí.

Algunos fallos no fallan lo suficientemente alto.

Datadog, Grafana, New Relic — solo pueden mostrar las señales que tu código realmente produjo. Si la excepción fue silenciada, la transacción no fue revertida o la llamada HTTP no tenía timeout, ningún dashboard va a conjurar esa evidencia durante un incidente.

01

Una excepción desaparece

Capturada y nunca registrada, propagada ni tratada. Lo que sea que haya pasado, nadie lo sabrá.

02

Un fallo parece éxito

La excepción se convierte en false, null o un Optional vacío — y la causa original va con ella.

03

Una operación de escritura sin transacción

Si el segundo save falla, el primero ya fue confirmado y no hay rollback. Los datos quedan inconsistentes, silenciosamente.

04

Una llamada HTTP sin timeout

Un upstream lento retiene el hilo indefinidamente. Bajo carga, el pool se agota y todo el servicio deja de responder.

OrderService.java
public Order createOrder(OrderRequest req) {
  // sin @Transactional — si reserve() lanza,   // el order guardado nunca se revierte   Order order = orderRepo.save(new Order(req));
  inventory.reserve(req.items());
  return order;
}

  Mono<String> response = webClient.get(uri);
  // sin .timeout() — bloquea indefinidamente   return response.block();
}

Cómo funciona

DiagScope lee los archivos fuente y razona sobre la estructura. Nunca compila tu proyecto, nunca ejecuta tu código y nunca envía nada fuera de tu máquina.

Parse

Lee todos los archivos fuente

Todos los archivos .java y .kt se analizan en un modelo neutro de lenguaje. Llamadas a métodos, anotaciones, bloques catch, loops — todo lo que las reglas necesitan para razonar.

Construir flujos

Sigue rutas de ejecución reales

Para cada entrypoint — endpoint REST, listener Kafka, método @Scheduled o cualquier método público — sigue el grafo de llamadas y recopila todos los métodos alcanzables en un flujo.

Ejecutar reglas

Cada hallazgo tiene contexto

Cada regla ve todos los métodos en todos los flujos. Los hallazgos nombran el entrypoint que lleva al problema, para que sepas el contexto operacional. Los caminos ambiguos se reportan como límites de flujo, nunca como suposiciones.

diagscope rules lista todas las reglas con severidad y versión. diagscope explain <ID> imprime qué detecta la regla, por qué importa y cómo corregirla. Suprime un hallazgo específico con // diagscope:ignore RULE_ID -- motivo. Tres reglas son exclusivas de Kotlin (coroutines); el resto funciona igual en Java y Kotlin.

Comienza en dos comandos

DiagScope se distribuye via Homebrew. Java 25 se instala automáticamente — no hay nada más que configurar.

1

Instalar

Agrega el tap e instala. Java 25 viene incluido.

$ brew tap DiagScope/tap
$ brew install diagscope
2

Ejecutar

Apunta a cualquier proyecto Java o Kotlin. Sin necesidad de compilar.

$ diagscope scan --project /ruta/al/proyecto
3

Leer el reporte

Resultados en target/diagscope/ (Maven) o build/diagscope/ (Gradle).

report.html  ← interactivo
report.md    ← para revisión de PR
result.json  ← automatización
↑

Actualizar

$ brew update && brew upgrade diagscope

Spring, Quarkus, Micronaut

Los endpoints REST, listeners Kafka y jobs @Scheduled se detectan automáticamente como entrypoints.

$ diagscope scan --project .

Java o Kotlin sin framework

Librerías y proyectos simples — cada método público se convierte en entrypoint.

$ diagscope scan --project . --entrypoint PUBLIC_METHOD

CI — solo archivos modificados

Falla el build solo en hallazgos de archivos tocados por este PR.

$ diagscope scan --project . \
  --changed-since origin/main --fail-on ERROR

Baseline — gate solo nuevos hallazgos

Registra el estado actual y bloquea solo regresiones futuras.

$ diagscope scan --project . --update-baseline
$ diagscope scan --project . --baseline --fail-on ERROR

Explorar las reglas

$ diagscope rules
$ diagscope explain SILENT_CATCH

Seguro para ejecutar en código empresarial

DiagScope está diseñado desde el principio para funcionar en bases de código propietarias sin generar ninguna preocupación de datos o seguridad.

Tu código nunca sale de tu máquina

DiagScope no realiza peticiones de red durante el análisis. Sin telemetría, sin verificaciones de licencia, sin ningún backend en la nube.

Nada se recopila ni transmite

Sin analytics, sin reportes de errores, sin pings de actualización. DiagScope no sabe que lo ejecutaste, qué proyecto analizaste ni qué encontró.

Ningún código se ejecuta ni compila

La herramienta solo lee archivos .java y .kt. Nunca invoca el compilador, ejecuta tests ni carga las clases de tu aplicación.

Los resultados se quedan donde los pones

Los archivos de salida se escriben en tu sistema de archivos local. Nada se sube ni comparte a menos que lo elijas explícitamente.

Verificable por diseño

DiagScope es un JAR autocontenido. sudo lsof -i -p <pid> o Wireshark confirma cero conexiones de red mientras se ejecuta.

Código fuente disponible para tu equipo

Los miembros autorizados del equipo pueden solicitar acceso al repositorio fuente para auditar la herramienta antes de desplegarla internamente.
