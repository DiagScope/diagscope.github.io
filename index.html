Find the code that hides failures before production does

DiagScope scans Java and Kotlin projects for patterns that silently destroy diagnostic evidence — swallowed exceptions, missing transactions, HTTP calls without timeouts. Runs locally, no data leaves your machine.

$ brew tap DiagScope/tap && brew install diagscope
$ diagscope scan --project .

What it finds

Code that fails silently

82 rules across exceptions, transactions, concurrency, Kafka, performance, security, and more. Every finding names the entrypoint that reaches the problem.

SILENT_CATCH

Swallowed exception

Caught and never logged or re-thrown — the failure simply disappears.

FUTURE_GET_NO_TIMEOUT

Blocking call without timeout

A thread hangs indefinitely waiting for a result that may never come.

MISSING_TX_ANNOTATION

Write without transaction

If a later step fails, the first write is committed and cannot be rolled back.

HTTP_TIMEOUT_NOT_SET

HTTP call with no timeout

A slow upstream exhausts the thread pool and takes the whole service down.

N_PLUS_ONE_QUERY_RISK

N+1 query in loop

A database call inside a loop — scales linearly and degrades with data growth.

KAFKA_SEND_RESULT_IGNORED

Kafka send not observed

The publish result is dropped — failures are invisible to the caller.

Install

Up and running in two commands

01 — Add the tap

Install via Homebrew

Java is bundled automatically — nothing else to configure.

$ brew tap DiagScope/tap
$ brew install diagscope
02 — Scan

Point at a project

No build step required. Works with Maven and Gradle layouts.

$ diagscope scan --project .
03 — Read the report

Results in seconds

HTML, Markdown, and JSON outputs in target/diagscope/ or build/diagscope/.

report.html  ← interactive report.md   ← for PR review result.json  ← automation
Usage

Common commands

Scan a Spring project

REST endpoints, Kafka listeners, and scheduled jobs are detected as entrypoints automatically.

$ diagscope scan --project .

CI gate — only new findings

Fail the build only on findings introduced in this PR, leaving existing issues for later.

$ diagscope scan --project . --update-baseline $ diagscope scan --project . --baseline --fail-on ERROR

Explain a finding

Get the full description, why it matters, and how to fix it.

$ diagscope explain SILENT_CATCH

List all rules

See all 82 rules with severity, category, and version.

$ diagscope rules
