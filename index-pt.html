quando quebrar em produção?

DiagScope segue fluxos de execução reais e encontra código que destrói silenciosamente as evidências de diagnóstico — antes que um incidente force você a descobrir que elas nunca estiveram lá.

Algumas falhas não falham alto o suficiente.

Datadog, Grafana, New Relic — eles só conseguem exibir os sinais que o seu código realmente produziu. Se a exceção foi engolida, a transação não foi desfeita ou a chamada HTTP não tinha timeout, nenhum dashboard vai conjurar essa evidência durante um incidente.

01

Uma exceção desaparece

Capturada e nunca logada, propagada ou tratada. O que quer que tenha acontecido, ninguém vai saber.

02

Uma falha parece sucesso

A exceção vira false, null ou um Optional vazio — e a causa original vai junto.

03

Uma operação de escrita sem transação

Se o segundo save falhar, o primeiro já foi commitado e não há rollback. Os dados ficam inconsistentes, silenciosamente.

04

Uma chamada HTTP sem timeout

Um upstream lento segura a thread indefinidamente. Sob carga, o pool se esgota e o serviço inteiro para de responder.

Como funciona

DiagScope lê os arquivos fonte e raciocina sobre a estrutura. Não compila o projeto, não executa o código e não envia nada para fora da sua máquina.

Parse

Lê todos os arquivos fonte

Todos os arquivos .java e .kt são analisados em um modelo neutro de linguagem. Chamadas de método, anotações, blocos catch, loops — tudo que as regras precisam raciocinar.

Construir fluxos

Segue caminhos de execução reais

Para cada entrypoint — endpoint REST, listener Kafka, método @Scheduled ou qualquer método público — ele segue o grafo de chamadas e coleta todos os métodos alcançáveis em um fluxo.

Executar regras

Todo problema tem contexto

Cada regra vê todos os métodos em todos os fluxos. Os problemas identificam o entrypoint que leva ao problema, para que você saiba o contexto operacional. Caminhos ambíguos são reportados como limites de fluxo, nunca como suposições.

Cada regra tem uma afirmação precisa, uma impressão digital determinística e um nível de confiança. Execute diagscope explain <RULE_ID> para entender o que um problema significa e como corrigi-lo.

Comece em dois comandos

O DiagScope é distribuído via Homebrew. O Java 25 é instalado automaticamente — não é necessário configurar mais nada.

1

Instalar

Adicione o tap e instale. O Java 25 vem junto.

$ brew tap DiagScope/tap
$ brew install diagscope
2

Executar

Aponte para qualquer projeto Java ou Kotlin. Sem necessidade de build.

$ diagscope scan --project /caminho/do/projeto
3

Ler o relatório

Resultados em target/diagscope/ (Maven) ou build/diagscope/ (Gradle).

report.html  ← interativo
report.md    ← para revisão de PR
result.json  ← automação
↑

Atualizar

$ brew update && brew upgrade diagscope

Spring, Quarkus, Micronaut

Endpoints REST, listeners Kafka e jobs @Scheduled são detectados automaticamente como entrypoints.

$ diagscope scan --project .

Java ou Kotlin sem framework

Bibliotecas e projetos simples — todo método público vira entrypoint.

$ diagscope scan --project . --entrypoint PUBLIC_METHOD

CI — apenas arquivos alterados

Falhe o build apenas em problemas nos arquivos tocados por este PR.

$ diagscope scan --project . \
  --changed-since origin/main --fail-on ERROR

Baseline — gate apenas novos problemas

Registre o estado atual e bloqueie apenas regressões futuras.

$ diagscope scan --project . --update-baseline
$ diagscope scan --project . --baseline --fail-on ERROR

Explorar as regras

$ diagscope rules
$ diagscope explain SILENT_CATCH

Seguro para rodar no código da empresa

O DiagScope foi projetado para funcionar em bases de código proprietárias sem levantar qualquer preocupação de dados ou segurança.

Seu código nunca sai da sua máquina

O DiagScope não faz requisições de rede durante a análise. Sem telemetria, sem verificações de licença, sem backend em nuvem de qualquer tipo.

Nada é coletado ou transmitido

Sem analytics, sem relatório de erros, sem pings de atualização. O DiagScope não sabe que você o executou, qual projeto analisou ou o que encontrou.

Nenhum código é executado ou compilado

A ferramenta lê apenas arquivos .java e .kt. Nunca invoca o compilador, executa testes ou carrega as classes da sua aplicação.

Os resultados ficam onde você os coloca

Os arquivos de saída são gravados no seu sistema de arquivos local. Nada é enviado ou compartilhado a menos que você escolha explicitamente fazer isso.

Verificável por design

O DiagScope é um JAR autocontido. sudo lsof -i -p <pid> ou Wireshark confirma zero conexões de rede enquanto ele executa.

Código-fonte disponível para seu time

Membros autorizados da equipe podem solicitar acesso ao repositório fonte para auditar a ferramenta antes de implantá-la internamente.
